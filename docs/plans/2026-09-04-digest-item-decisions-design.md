# 周报快照项目决定设计

## 目标

允许用户在历史周报中把每个项目标记为“待定 / 保留 / 移除”，让快照成为可复盘、可修订的人工工作台，而不是一次性只读结果。

## 方案

- 推荐在历史卡片内提供三态按钮，直接更新现有 `digest_items.decision`。
- 备选是打开独立详情页，或追加新的审阅事件表；前者增加导航成本，后者需要迁移且当前单用户场景暂无必要。
- 新增 `PATCH /api/digests/[digestId]/items/[digestItemId]`，只接受 `pending`、`kept`、`dismissed`，服务端校验 item 必须属于指定 digest。
- 更新成功返回完整快照，客户端以服务端结果替换历史项；分数、理由、位置和仓库信息保持原快照，不重新计算。

## 交互与边界

- 历史卡片保留现有周期、状态、保存时间和项目列表；每个项目旁显示三态决定。
- 请求期间仅禁用当前项目的按钮，错误显示在历史区顶部，不丢失其他状态。
- 操作可逆，不删除记录、不发布、不发送，也不改变当前周报预览。
- 继续复用现有表，不新增迁移。

## 验收

- 领域层更新成功返回快照，错误 ID 或跨 digest item 返回空结果且不改数据。
- Route Handler 拒绝非 JSON、非法决策和超长 body，并返回稳定状态码。
- UI 覆盖 pending/kept/dismissed 三态、保存中禁用和失败提示。
- Vitest、lint、typecheck、build、Playwright 通过。
