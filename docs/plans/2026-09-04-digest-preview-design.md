# Sprint 3：周报预览与快照设计

## 目标

把当前动态推荐信号整理成一份可人工调整的周报预览。预览只读取本地仓库、分析、兴趣和反馈；用户勾选需要保留的项目后点击“保存为周报快照”，服务端重新计算分数和理由，再写入 `digests` / `digest_items`。本轮不发送邮件、不自动运行、不调用外部模型。

## 数据流

1. `GET /api/digests/preview` 从本地收藏库取最多 8 个候选，按 ranking 分数倒序，生成最近 7 天的预览周期。
2. UI 允许取消勾选项目，客户端只提交仓库 ID 列表，不提交分数或理由。
3. `POST /api/digests/preview` 服务端重新计算全部候选，过滤并校验客户端选择，事务写入一条 `draft` digest 和对应的 `digest_items`；每个 item 保存当时的 score、reasons 和 position。
4. 返回快照摘要和条目，供 UI 显示“已保存”。

## 取舍

- 复用现有 digest 表，不新增迁移。
- 周期默认按 UTC 最近 7 天；暂不开放主题配额、来源配额和邮件通知设置。
- 没有仓库或没有可解释信号时仍展示空状态，不伪造推荐；保存前至少需要保留 1 条。
- 每次确认生成一条新草稿快照，保留历史，后续可在周报页增加历史列表和发布操作。

## UI 状态

- loading：候选卡片骨架与 `aria-busy`。
- empty：说明需要先导入项目或配置兴趣规则。
- preview：卡片显示分数、理由、来源覆盖度和勾选框；顶部显示周期与选中数量。
- saving：禁用勾选和按钮，显示 spinner。
- saved：展示快照 ID、保存时间和“继续调整/重新生成”入口。
- error：保留当前选择，显示重试提示。

## 验收

- 单测覆盖预览排序、客户端选择过滤、至少一条校验、快照 score/reasons 持久化和历史不覆盖。
- API 不信任客户端 score/reasons，确认时服务端重算。
- UI 使用现有视觉 token、键盘焦点和明确的空/错/加载状态。
- `lint`、`typecheck`、`test`、`build`、E2E 通过。
