# 收藏库卡片与工作流分类设计

## 目标

把收藏库从“仓库列表”改成“项目复盘工作台”：用户先按工作流阶段理解项目，再在卡片上看到为什么关注、下一步做什么和本地推荐分数，避免做成 GitHub 的社交/代码浏览副本。

## 方案

- 推荐保留现有搜索和状态筛选，将结果按状态分组为「候选 / 试用中 / 已采用 / 参考 / 已放弃」；每组显示阶段说明和数量。
- 每个项目使用可聚焦卡片：项目名、两行描述、状态、来源、标签、匹配分、更新时间和下一步行动。Stars、Forks 不再作为卡片主视觉，只保留在详情面板中作为上下文。
- 备选是纯看板列或保留列表加密度切换。看板在项目数量增长后容易横向拥挤，密度切换会增加状态管理；当前单用户 MVP 先用响应式分组卡片。
- 卡片仍通过选择打开现有详情面板，编辑状态/标签/笔记和分析/反馈流程不变。

## 交互与视觉

- 桌面两列卡片，移动端单列；组标题采用阶段色标和简短动作文案。
- 选中卡片使用浅色强调背景和 `aria-pressed`，焦点使用统一可见 ring；来源、标签和状态使用低噪声 pill。
- 空、加载、筛选无结果沿用现有状态；卡片不添加点赞、评论、关注数或活动时间线。

## 验收

- 收藏库结果按工作流状态分组渲染，筛选后分组仍正确。
- 卡片不突出 Stars/Forks，突出下一步行动和推荐分数。
- 选择卡片仍能打开详情并保留当前编辑行为。
- E2E 导入弹窗、导航和卡片可见性不回归；lint、typecheck、build 通过。
