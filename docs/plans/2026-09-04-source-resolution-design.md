# 已接受来源的仓库解析与入库

延续现有本地单用户、人审后处理的路线；不引入模型、后台批量任务或对外发布。

## 本轮边界

- 接受来源只确认线索；用户另行点击“解析并入库”才触发 GitHub 只读查询。
- 严格规范化 GitHub 仓库地址，单来源最多 20 个引用；已有仓库直接复用。
- 所有查询成功后，在同一事务内 Upsert 仓库、创建默认用户元数据、关联原始来源证据。保持既有用户笔记和状态。
- 完成时间与关联数量可见；重复请求幂等。失败不写入部分仓库，记录安全错误与重试时间。
- 两分钟处理租约和唯一尝试标识防止重复执行，过期可恢复；审核撤销或来源内容变化后，旧请求不得提交。

## 取舍

显式处理比自动批量更便于控制外网请求；先确定性解析比直接引入 AI 更易核对证据。后台调度和 AI 整理留给后续阶段。

## 验收

验收计划包含：模拟 GitHub 响应和内存 SQLite 下的未审核拒绝、正常关联、跨来源去重、保护用户元数据、失败回滚、重复请求、租约恢复、审核撤销、内容变化、限流和非法引用；页面覆盖可操作、处理中、完成、失败重试状态。当前已落地未审核拒绝、正常关联、失败回滚、重复请求、内容变化和 UI 导航回归，其余并发/重试边界可在下一轮继续补齐。测试不得修改真实用户来源或请求外部 GitHub。
