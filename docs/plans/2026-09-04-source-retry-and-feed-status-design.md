# 来源重试与 RSS 状态设计

## 目标

让来源处理台能回答两个问题：RSS 最近一次同步是否成功，以及失败的 GitHub 引用解析是否已经到了可重试时间。调度逻辑保持确定性，页面只呈现工作流状态，不引入社交信息流。

## 范围

- `rss_feeds` 记录失败状态和错误信息；失败不覆盖上一次成功同步时间。
- 收件箱提供只读 RSS feed 状态摘要：最近尝试、上次成功、错误原因。
- `src/jobs/source-retry.ts` 提供可被 cron/手动入口调用的到期重试函数，只处理已接受且 `next_retry_at` 已到期的来源。
- 重试沿用 `resolveSourceItem` 的租约、幂等和原子入库约束；单次最多处理 10 条，避免一次调度放大外部请求。
- 本轮不在 Next 进程内常驻计时器，也不自动发送周报；外部调度器调用 API 即可。

## 数据流与错误处理

RSS 路由在 URL 有效且上游请求/解析失败时，把 feed 标记为 `error`，保留 etag、last-modified 和最近一次成功的 `last_fetched_at`。成功 200 或 304 会恢复 `active`。解析重试任务只选 `accepted + failed + next_retry_at <= now` 的来源；非重试错误仍可由卡片上的人工按钮触发。

## UI

在收件箱顶部增加低噪音的“RSS 同步状态”卡片组。每张卡片显示 feed 名称、状态、最近尝试、上次成功和错误提示；不展示 etag 等实现细节。解析失败卡片继续显示倒计时和人工重试按钮，状态颜色沿用待确认/已接受/已忽略的工作流标记。

## 验收

- RSS 成功、304、失败都能在状态查询中反映，失败不丢失上次成功时间。
- 到期任务只处理符合条件的来源，并返回每条解析结果；未到期来源保持不变。
- `pnpm lint`、`pnpm typecheck`、`pnpm test`、`pnpm build` 通过。
